# Вклад в проект

Спасибо, что хотите помочь.

## Процесс

1. Ветка, изменения, пул-реквест в `main`.
2. Все проверки зелёные: `harness check` и `./scripts/verify.sh` — то же самое
   крутится на PR.
3. Ревью.
4. Мёрж.

Ключевые изменения попадают в
[GitHub Releases](https://github.com/gently-whitesnow/bugget/releases) — это единственный
журнал изменений, отдельного CHANGELOG нет.

## Что проект берёт, а что нет

Миссия Bugget — **создавать процесс работы с багами, делая упор на удобство и
эффективность**. Это и есть фильтр: изменение принимается, если делает работу с багами
удобнее или быстрее.

## Дисциплина PR

Бюджет ревью — примерно **600 строк бизнес-логики на PR**. В бюджет **не входят**
сгенерированный код (`*.g.cs`, `frontend/src/shared/api/generated/*.d.ts`), тесты,
документация, форматирование и механические перемещения файлов.

Больше — режьте на слайсы и несите по очереди: крупная фича одним куском не ревьюится.

## Что должно быть в PR и в коммитах

Описание PR отвечает на вопрос «можно ли это влить»: что меняется и зачем.

Сообщение коммита — по шаблону harness: заголовок `<type>(<scope>): <суть>` и блоки
«Контекст», «Решение», «Границы», «Последствия». Шаблон печатает
`harness commit-message template`; после `harness setup` его подставляет git, а хук
`commit-msg` проверяет сообщение до создания коммита.

Архитектурное решение, которое переживёт этот PR, живёт не в коммите, а в ADR (`adrs/`).
Проверку не ослабляют ради зелёного прогона: политику `.harness.json` меняет владелец
репозитория, диагностика выключается только на весь репозиторий и с причиной (ADR-0016).

## Локальная разработка

Полный контур поднимается одной командой (см. [README](../README.md#быстрый-старт)):

```sh
cd deploy
docker compose -f docker-compose.yml -f docker-compose.dev.yml \
  --env-file env/dev.env --profile full up --build
```

Проверки перед пул-реквестом:

```sh
harness check                        # рамка репозитория
./scripts/verify.sh          # все гейты, это же крутится на PR
```

Шаги перечислены в самом `scripts/verify.sh`. Подробности — в [README](../README.md#проверки-качества).
