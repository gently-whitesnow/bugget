## Комментарий и шаг с вложениями — одним запросом

Сейчас запись создаётся отдельным запросом, вложения грузятся после неё. Если файл не
загрузился, фронт удаляет созданную запись (`frontend/src/pages/Report/lib/createWithAttachments.ts`).
Это не атомарно:

- Другие участники репорта видят, как запись появляется и тут же исчезает: создание и
  удаление приходят им по SignalR. Проверено вручную.
- Если вслед за загрузкой упадёт и удаление, запись останется, а повторная отправка из
  формы создаст дубль.

Что сделать:

- Эндпоинт `multipart`: текст и файлы, бэкенд создаёт всё в одной транзакции.
- Это новый публичный контракт: `specs/contracts/**/openapi.yaml`, перегенерация, ADR.
- После — убрать `createWithAttachments` и откат удалением на фронте.

## Скрепка принимает файлы любого типа

Бэкенд пропускает только белый список MIME (`backend/Bugget.Domain/Constants/AttachmentConstants.cs`):
картинки, видео, gif, текстовые форматы. Скрепка и вставка в `ComposerInput` берут любой
файл, поэтому о неподходящем типе, например PDF, пользователь узнаёт только после отправки.

Что сделать:

- Ограничить `<input type="file">` через `accept` тем же списком.
- Проверять тип при вставке из буфера и сразу объяснять, что файл не поддерживается.
- Решить, нужен ли PDF: сейчас его нет в белом списке, причина нигде не записана.
