# Атомарная выкладка frontend/backend

Frontend и backend совместимы только как согласованная пара образов. Смешанная версия —
операционная ошибка, а не поддерживаемый режим. Владелец каждого шага ниже — деплоер,
который проводит релиз.

## Выбор пары

1. Выберите один прошедший CI commit монорепозитория и один release-тег.
2. Запустите от этого commit `publish-backend` и `publish-frontend` с одинаковой версией.
3. Запишите неизменяемые digest обоих результатов:
   `ghcr.io/gently-whitesnow/bugget-api@sha256:…` и
   `ghcr.io/gently-whitesnow/bugget-ui@sha256:…`. Теги `latest` парой не считаются.
4. До переключения сохраните текущие два digest как rollback-пару.

## Переключение и проверка

1. Закройте внешний трафик на время переключения.
2. В одной ревизии конфигурации замените сразу оба image reference на выбранные digest.
3. Одним применением оркестратора пересоздайте backend и frontend. Не открывайте трафик,
   если обновился только один компонент; завершите пару либо сразу откатите оба.
4. Убедитесь по состоянию оркестратора, что запущены именно два записанных digest.
5. Через тот же ingress выполните вход, откройте список и карточку репорта, затем создайте
   или измените репорт. Проверьте отсутствие HTTP 4xx/5xx и ошибок загрузки frontend.
6. Только после проверки откройте внешний трафик.

## Совместный откат

Снова закройте трафик, одной ревизией верните **оба** сохранённых digest, примените её
одним запуском оркестратора и повторите проверку пары и smoke-сценарий. Частичный откат
одного образа запрещён; если совместный откат не завершён, трафик остаётся закрытым.

Эта гарантия ручная: publish-workflow собирают образы отдельно, а release workflow,
который принуждает пару, в репозитории отсутствует.
