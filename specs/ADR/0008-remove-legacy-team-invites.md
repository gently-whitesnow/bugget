# ADR-0008: Удаление legacy TTL-token инвайтов команд из публичного API

- **Статус:** Accepted
- **Дата:** 2026-07-28
- **Решение принял:** владелец продукта

## Контекст

Users API содержал пять маршрутов для SaaS-сценария одноразовых TTL-token инвайтов
команд. Единственный клиент API — фронтенд этого репозитория; он больше не имеет UI
этого сценария, но sidebar продолжал фоново запрашивать действующий инвайт. В self-hosted
это приводило к ошибке из-за неактуальной зависимости от `DomainOptions:BaseUrl`.

Рабочее self-hosted приглашение устроено иначе: оно передаёт `workspaceId` и `teamId`
в ссылке, а вступление выполняется через маршруты `/members/join`.

## Решение

Удаляем без периода совместимости пять legacy-маршрутов TTL-token инвайтов:

- `POST` и `GET /v1/workspaces/{workspaceId}/teams/{teamId}/invites`;
- `PUT` и `DELETE /v1/workspaces/{workspaceId}/teams/{teamId}/invites/{id}`;
- `POST /v1/invites/accept`.

Изменение атомарно: в одном PR меняются OpenAPI-источник, генерируемые C# и TypeScript
контракты, серверный код, фронтовые вызовы, контрактные снимки и инвентарь. Депрекация
не нужна, потому что другого клиента нет. Self-hosted ссылки с `workspaceId`/`teamId` и
оба маршрута `/members/join` не относятся к этому контракту и остаются.

Схема БД в этой программе не меняется. Таблица `team_invites`, индекс
`ux_team_invites_token_hash` и функции `create_team_invite`, `update_team_invite`,
`get_team_invite`, `delete_team_invite`, `accept_team_invite` становятся осиротевшими;
их удаление требует отдельной миграции.

## Последствия

- dashboard больше не отправляет запросы к `/invites` при открытии и поздней загрузке
  пользователя;
- внешний потребитель старых маршрутов получит 404 после обновления, что допустимо для
  удалённого публичного контракта;
- конфигурация `TeamsOptions` больше не содержит секретный pepper и время жизни
  инвайта;
- будущая задача должна убрать осиротевшие объекты БД отдельной миграцией.
